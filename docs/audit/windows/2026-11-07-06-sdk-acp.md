2. W-SDK-02：扩展 `nativeTargets`、发布矩阵和 `libfx.win32-*.node` 命名验证，让 Windows prebuild 成为真实产物。
3. W-SDK-01：同步 `nativePackages`、optional dependencies 和 `getBackendInfo()` 的平台表，打通 Windows native discovery。
4. W-CI-12：增加 Windows SDK/ACP/package qualification job；没有 runner，前三项无法保持不回归。
5. W-E2E-11：建立 Windows 平台测试清单并修正 `win32` 分支登记，随后把 W-E2E-10 的 CLI/ACP 子集从 tmux/Bash 依赖中拆出来。

W-SDK-05 是默认用户体验的缓解路径，应作为并行交付：在 native 支持落地前，用 Windows CI 明确验证 packaged WASM + JSPI 的 Node 版本范围，并同步 README 与 `getBackendInfo()` 文案。

## 验证清单

- Windows x64/arm64 上 `node -e "require('libfx').getBackendInfo({backend:'native'}).then(console.log)"` 返回 `native`；`getBackendInfo({backend:'wasm'})` 在支持 JSPI 的 Node 上返回 `wasm-jspi`。
- `npm pack ./sdk/dist/libfx --json` 的文件表含 `node.js`、`node.cjs`、`node-wasm.js`、`fx-core.wasm`、`fx-term.wasm`；平台包表含两个 `win32` 包，且各自 `os` / `cpu` 与本机一致。
- Windows runner 上 `zig build libfx-napi -Dnapi-surface=core -Doptimize=ReleaseSafe`，随后 `npm run --prefix sdk test:node-napi` 和一个 `createFxEngine({ backend: "native" })` 的 checkpoint/close 往返通过。
- Windows runner 上 `zig build fx-core-wasm -Dwasm-surface=core`、`zig build fx-term-wasm -Dwasm-surface=term`，`npm run --prefix sdk test:node-wasm` 与 `npm run --prefix sdk test:browser-wasm` 通过。
- Windows PowerShell 7 通过匿名 pipe 向 `fx acp` 发 UTF-8 LF、UTF-8 CRLF、UTF-8 BOM + LF、UTF-16LE、半帧后 EOF；观察 stdout 为 UTF-8 LF 帧、错误诊断明确、stdin 关闭后进程退出且 stderr 干净。
- `zig build test -Doptimize=ReleaseSafe` 在 Windows 包含 ACP 的 CRLF、BOM、UTF-16、EOF 和 `io.readFd()` 管道测试；`FX_SOUND=0 bun test <windows-platform-tests.json 中文件>` 在 Windows runner 上通过，skipped 数量被记录。
- `cd tests/e2e && bun test ci-shards.test.ts` 检查 macOS 与 Windows 两份平台清单；`scripts/detect-windows-need.sh` 对 Windows-only 产物和协议改动返回需要的信号。
- `gh run list --workflow=ci.yml` 与发布 workflow 的 artifacts 中可见 Windows job 和 `libfx.win32-*.node`；CI 结果属于修复后的精确 commit。
- 所有验证命令只使用占位凭据或环境变量名，例如 `AI_GATEWAY_API_KEY` / `VERCEL_OIDC_TOKEN`；不把本机配置值写入日志、测试夹具或报告。
